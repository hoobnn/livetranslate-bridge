# UX review — 2026-09-22

## Intent

Make the subtitle window a calm reading surface with clear session controls, using native macOS navigation, settings, confirmation dialogs, typography, and accessibility behavior. This iteration builds on the existing uncommitted redesign; it does not replace the audio pipeline.

References: [Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/), [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility).

## Changes

- Name the two destinations in the toolbar. Keep the subtitle view mounted while inspecting diagnostics, retaining its scroll and follow state. Only the active page contributes subtitle toolbar actions.
- Show the selected source application's name separately from the language/mode summary. Move the transcript count to this secondary line so changing counts do not squeeze the transport control.
- Keep collapsed logs quiet: no continuously changing raw message, line count, or debugging buttons on the reading surface. Expanded logs still expose the original controls.
- Avoid animated automatic scroll competing with streaming updates. Suppress automatic following throughout user scrolling, including deceleration. Keep the explicit return-to-latest action.
- Keep speaker lanes distinct but left-align wrapped text for reading. Increase timestamp size and contrast.
- Show copy feedback and provide Command-Shift-C. Ask before clearing subtitles, with an explicit cancel action. Clearing does not stop the session.
- Keep error details visible even when the transcript is nonempty. Add a direct Settings entry point.
- Show microphone/app settings according to the selected capture scope. Name missing saved devices without silently changing the route. Explain why devices are locked during a session.
- Add mute/restore controls, prevent concurrent device refreshes, and expose all four sliders and mute buttons to accessibility. Audio settings are available in the Settings window as well as the session popover.
- Stabilize Settings window dimensions. Disable credential editing during load/save, trim accidental surrounding whitespace, prevent overlapping writes, and preserve fields on failed deletion. Confirm credential removal.
- Respect Reduce Motion at both window roots and use opaque cards for Increase Contrast. Name icon-only actions for accessibility.
- Update Chinese and English capture explanations to describe app audio rather than requiring a phone call.

## Reproduce

```sh
xcodebuild -project LiveTranslateBridge.xcodeproj -scheme LiveTranslateBridge \
  -configuration Debug -derivedDataPath /tmp/livetranslate-bridge-ux \
  test -only-testing:LiveTranslateBridgeTests \
  -only-testing:LiveTranslateBridgeUITests CODE_SIGNING_ALLOWED=YES
```

The UI suite launches with `-sampleBoard`; it does not require credentials. To inspect a sample board manually, launch the Debug executable with the same argument. The built app is `/tmp/livetranslate-bridge-ux/Build/Products/Debug/LiveTranslateBridge.app`.

## Visual refinement — minimal interface

The subsequent visual pass removes the ambient gradients, floating session card, status capsule, animated status ring, decorative empty-state medallion, diagnostic icon tiles, and content-card shadows. The reading surface now uses the system text background in both appearances. A single separator divides controls from content; source and status sit on a secondary line. The language pair uses primary text, with blue reserved for the local speaker and primary action and neutral gray for the remote speaker. Semantic failure/waiting colors remain available.

The two existing UI regressions also retain window-only screenshots of the populated subtitle board in light and dark appearance and of diagnostics in dark appearance. These are sample conversations, not captured calls. Visual inspection covers text hierarchy, controls, spacing, and legibility; aesthetic preference remains a human judgment.

Final visual verification: both UI regressions passed after the visual changes; the diagnostics round-trip passed again with the DEBUG-only `-previewDark` flag. Inspected [light subtitles](assets/ux/subtitles-light.png), [dark subtitles](assets/ux/subtitles-dark.png), and [dark diagnostics](assets/ux/diagnostics-dark.png). Both appearances preserve readable foregrounds and visible primary controls. The app was reopened without preview flags after verification.

### Restrained color and source identity

At the user's request, the language pair and speaker rails now use muted blue and teal. The background stays neutral. The source row shows an 18-point native application icon, resolved only when the selected bundle ID changes. FaceTime's audio service resolves to the FaceTime app; unavailable app bundles use a neutral fallback, and microphone-only mode uses a microphone symbol. Verified the actual NetEase Music icon and restrained language colors in the running app. Earlier screenshots above document the preceding neutral-palette iteration.

### Screenshot-driven detail fixes

- Treat whitespace, line breaks, zero-width spaces, and byte-order marks as empty subtitle content. Exclude such turns from rendered rows, counts, and copied text; fall back to readable source text when the translation is blank. The screenshot's actual service payload was not captured, so this verifies the reproduced whitespace failure rather than claiming every possible blank-row cause is eliminated.
- Use the native bordered Stop button to avoid black text on a dark secondary fill.
- Remove the duplicate toolbar title using the native toolbar API while preserving the accessible window title. Keep actions explicitly in the primary-action area.
- Widen the session popover, bottom-align language controls and swap button, use concise language names, increase section-label contrast, and provide a quiet opaque surface with a subtle boundary.
- Validation: 95 unit tests and 2 UI tests passed. Final builds and manual popover/window inspection passed. Real service output was not replayed during this pass.

### Alignment audit

The macOS SwiftUI Picker and Slider in these forms kept their intrinsic control width even inside wider frames. Replaced the affected session controls and sliders with small AppKit-backed native wrappers that fill their proposed width while retaining native actions, keyboard behavior, and accessibility roles.

- Session content: 322-point shared width; two 139-point language controls, a centered 28-point swap action, and two 8-point gaps. Both segmented controls fill the same content width with equally sized segments.
- Audio rows: a common 120-point label column, fixed mute-button and percentage columns, and genuinely expanding slider tracks. All four rows have identical horizontal boundaries. Removed dense tick marks.
- Service rows: the same label column, aligned endpoint labels and sliders, right-aligned values, and no duplicated slider labels. Long labels can wrap instead of clipping.
- Verified actual session and audio/settings screenshots, capture-scope round trip, and service-slider value propagation (0.20 -> 0.25 -> 0.20). Four audio sliders and both service sliders are exposed in accessibility. Two existing UI regressions passed. User audio volume selections were not changed by the verification.
