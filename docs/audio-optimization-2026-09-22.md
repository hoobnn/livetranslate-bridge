# 音频链路优化记录（2026-09-22）

## 已实施

- 保留 Process Tap + 麦克风 AVAudioEngine + 双向云端翻译架构。
- 远端混音成功建立就接管源应用直通，原声 0% 不再绕过静音；播放失败则保留直通并提示。
- 翻译模式在路由可用时持续请求译声，0% 只改变播放增益，调高滑块不再需要重启网络会话。
- 麦克风与所选应用播放状态解耦。应用暂停不会停止麦克风；停止后到达的权限回调不能重新打开采集。
- 指定输入丢失不回退默认麦克风；已知回环输入与输出重合时阻止启动。普通 USB 声卡/耳机的双向能力不再当作回环依据。
- 每秒在后台检查所选端点的 ID、存活、采样率、缓冲大小、声道，以及所选默认设备变化。发生变化时重建会话，保留已有字幕并封存未完成条目。恢复包含重新连接翻译服务，有短暂缺口；不是无缝热切换。
- 原声转换器支持声道数变化，单声道复制到输出通道；源/目标格式变化重建转换器。送云端的重采样器也随输入格式变化更新。
- 播放器所有引擎操作串行化，完成回调仅异步记账，避免 stop 同步回调死锁和 schedule/stop 竞态；节点启动在后台完成。
- 采集与原声回放使用预分配环形队列，实时回调不持有播放器路由锁。队列带有效期与会话代次，旧 socket 回调不能向替换后的播放器写入。
- 原声待播超过 250 ms 时清掉旧待播追赶实时位置；译声待播最多 15 秒，超限后丢弃当前回复的剩余语音并明确提示，字幕继续。这是有损降级，不保证语句完整。
- 新增「跳过译声」：停止两侧待播译声，丢弃当前未结束回复的后续语音，不停止原声、转录和翻译。已结束回复的跳过不会误吞下一回复。
- 混音末端增加 Apple Peak Limiter；增益改变约 25 ms 渐变。可选自动降低远端原声：译声可听且正在排队/播放时将原声降到用户设定的 25%，结束后恢复。
- 日志记录原声/译声队列时长、采集丢帧、过期块和服务端 speech-stopped 到后续首块译声收到的间隔。该间隔不是精确逐句端到端延迟，也不包括声卡真实播放延迟。

## 自动验证

```sh
xcodebuild -project LiveTranslateBridge.xcodeproj \
  -scheme LiveTranslateBridge -configuration Debug \
  -derivedDataPath /tmp/livetranslate-audio-opt \
  -only-testing:LiveTranslateBridgeTests \
  test CODE_SIGNING_ALLOWED=YES
```

离线播放测试走生产混音/限幅图，通过 AVAudioEngine manual rendering 输出缓冲，不打开真实麦克风或音频输出。新增覆盖：

- 单声道原声在左右声道均有非零信号；44.1/48/32 kHz 格式切换仍输出非零信号。
- 原声音量 0 时输出静音；停止后可重复启动。
- 两路高增益信号混合后经过限幅，输出峰值不超过测试容差。
- 并发入队和停止无崩溃；积压上限、跳过与下一回复恢复符合约定。
- 原声在跳过译声后继续输出；旧 socket 代次被拒绝；过期和旧采集代次不送往消费端。
- 指定输入缺失与跟随默认输入有不同语义；双向物理声卡不误报回环。

本轮完整单元测试：107 项通过、0 项失败。未把自动测试当作真实通话链路验收。

## 实机待验收与边界

1. 从原声 0% 启动播放器，确认源应用直通被静音，调到 100% 后恢复单路原声；译声从 0% 调高应恢复播放。
2. 真实麦克风 → 原声/译声混音 → BlackHole → 通话应用录音/对端监听，确认信号实际到达；本 App 有输出电平不能代替这项验收。
3. 会话中拔插指定耳机/麦克风，并切换默认设备，观察暂停、恢复和字幕保留。检查恢复时实际硬件格式及 TCC 权限。
4. 至少 30 分钟双向通话，观察队列上限、译声积压提示和跳过；同时检查自动压低原声是否影响听感。
5. 声学回声消除尚未接入。系统 SDK 的 `AVAudioIONode.setVoiceProcessingEnabled` 要求输入和输出共同进入 Voice Processing 模式且格式一致；当前独立输入、监听、虚拟输出引擎必须先验证播放参考与选定设备兼容性。防止数字回灌不等于消除扬声器串入麦克风。
6. 未自带虚拟麦克风驱动；仍使用用户安装的 BlackHole 等设备。未知第三方虚拟设备没有仅凭双向通道进行强制拦截。
7. 没有改动云端断句默认值或底层麦克风 100 ms 缓冲，也没有宣称延迟改善的实测数值。后续应以真实采集/发送/回复/硬件播放时间点进行同条件对照。
